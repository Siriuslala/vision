# LLaVA-OneVision 数据构造

LLaVA-OneVision 汇集了不同来源的图像问答，任务包括识别、空间关系、几何、表格和一般视觉问答。已检查记录通常没有独立的局部观察轨迹。构造过程先按来源恢复题目和最终答案，再由本地教师生成窗口与自然语言推理，并检查图像是否支持这些判断。

## 1. 数据结构与任务范围

来源文件按子集存放，Parquet 直接内嵌图像。转换器按批读取已经完成的文件，不需要整包解压，也不修改下载目录。

| 字段 | 含义与转换方式 |
| --- | --- |
| `id` | 子集内部样本编号，与子集名称共同确定来源身份 |
| `image` | 包含内嵌 `bytes` 和可选路径；无图记录不进入当前流程 |
| `conversations` | 消息列表；已支持的一轮问答由 `human` 问题和 `gpt` 回答组成 |
| `data_source` | 子集名称，用于选择任务映射和答案处理规则 |

图像占位符 `<image>` 从问题中移除，其余题干、选项与回答要求保留。转换器目前支持一张图的一轮问答；多轮对话需要另外设计上下文保存方式，不能将依赖前文的问题直接拆成独立样本。

已支持来源按下表处理。子集名称以代码中的完整名称为准；尚未分析的来源应先检查数据，再增加对应规则。

| 子集 | 当前任务类型 | 值得优先检查的内容 |
| --- | --- | --- |
| CLEVR-Math、Super-CLEVR | `spatial_reasoning` | 参照物定位、关系链、属性比较和假设场景变换 |
| GEOS、GeoQA+、Geometry3K、UniGeo | `spatial_reasoning` | 图中标记与几何关系的联合读取 |
| TabMWP | `table_qa` | 多行价格、跨列数值和条件比较 |
| FigureQA | `chart_qa` | 两个图形系列或类别的比较 |
| MapQA、MathV360K_TQA、VQA-AS、VQA-RAD、PMC-VQA | `general_vqa` | 地图图例、区域或其他任务相关细节 |
| IconQA | `general_vqa`，计数题需另行处理 | 直接计数需要实例标注与计数过程 metadata |
| VisualWebInstruct | `general_vqa` 或明确的 `captioning` | 答案边界及长回答是否只是描述图片 |

## 2. 当前发现的问题

混合数据的主要困难是不同子集的任务含义和答案形式并不统一。下列问题需要集中检查，不能仅依靠公共格式转换解决。

1. **来源答案可能与图片矛盾。** 早期 CLEVR-Math 试制中，删除所有球后的数量与可见物体数量不符。教师必须先独立观察，再与来源答案比较；不一致时保留原始标签并记录拒绝原因。
2. **最终答案不一定有明确边界。** 部分回答混合推导和结论，不能把整个回答当作最终答案，也不能任意截取最后一个数字。
3. **对话可能依赖前文。** 当前实现拒绝多轮记录，直到能完整保存上下文。
4. **直接计数需要实例信息。** 普通 bbox 轨迹不能替代计数协议要求的目标集合、局部数量与累计数。明显计数题需要转交相应构造流程。
5. **来源划分不能保证评测隔离。** 混合数据的 train 分片可能来自上游评测题目，正式训练前仍需要跨来源去重和外部测试重叠检查。

## 3. 问题与答案的提取

转换器使用明确的文本结构提取最终答案，例如 `<answer>` 标签或已确认的 `The answer is ...` 前缀。选择题答案必须属于题目给出的选项标识。短直接回答保留为文本；数值字符串保持来源形式，避免自行改变单位或容差。

长描述仅在题目明确要求 caption 时作为最终回答保留。缺少明确答案边界的推导文本进入拒绝记录，等待来源专用规则。原始对话和提取方式写入离线 metadata，便于检查；原始回答不会自动转换为自然语言推理事件。

## 4. 观察轨迹与自动检查

教师首先识别题目的视觉证据，再生成观察顺序。Super-CLEVR 的关系问题适合“定位参照物 → 读取相关目标 → 判断属性”；TabMWP 的购买问题适合“读取第一项价格 → 读取第二项价格 → 求和并与预算比较”。这些步骤具有明确的信息依赖，优先于重复读取同一个目标。

2026-09-15 抽读发现，TabMWP 的 `identity_235` 和 `identity_248` 分别要求将两项商品价格与预算比较；Super-CLEVR 的 `identity_269` 和 `identity_380` 需要先定位参照物再判断目标属性。这些是多次读取的试制选择，是否最终需要两次窗口以及能否通过检查，仍由实际图像和生成结果决定。

自动检查需要确认窗口同时保留目标与必要参照，自然语言只使用图片中可以确认的事实，并完整支持最终答案。来源短答案可以监督最后输出，但不能证明教师生成的中间判断正确。通过检查后，按照公共流程生成两种 reasoning mode，并按读取次数与是否纠错分别存储。

## 5. 实现与运行

`data/sft/datasets/llava.py` 的 `iter_tasks` 输出来源问题，`iter_candidates` 关联补充轨迹。来源编号由子集、原始 `id` 和轮次组成；标注的 `source_key` 还包含图像、问题和答案内容。任何一个内容变化后，旧标注都不能继续匹配。

生产入口为 `scripts/sft_data/produce_llava.sh`，教师生成入口为 `scripts/sft_data/propose_sft_regions.sh`。试制按子集选择少量不同图像，避免只检查文件排序最靠前的来源。输出及 viewer 配置遵循[公共说明](sft_production.md)。

已有测试检查选项答案、来源身份、缺少标注、多轮依赖、答案边界、非训练文件、无图输入和内容绑定。它们用于验证转换规则；教师推理、来源标签及训练特征的可辨性需要实际样本检查。

本地教师的自动生成与检查使用 `scripts/sft_data/produce_automatic.sh`。本轮实际展示的例子、没有通过的情况及解释见[试制报告](sft_pilot_v2.md)。
