# PixMo-Count 的分组计数数据生产

PixMo-Count 的训练记录提供计数类别、总数及实例 point。生产流程先下载并核验原图，再补充和审核实例 bbox，最后按空间顺序组织分组观察、局部计数和求和。输出采用数据格式 `1.1`，由公共生产器转换像素窗口为长边归一化坐标。输出状态保持 `pending`，实际视觉特征可辨性与批次质量验收完成后方可纳入训练。

## 1. 来源结构与适用范围

本地快照包括三个 Parquet 文件。来源 README 记载 train 为 36,916 条，validation 与 test 各为 540 条。实际 train schema 包含 `image_url`、`image_sha256`、`count`、`points` 和 `label`；其中 `points` 是含 `x`、`y` 两个 float32 数组的 struct，坐标单位为原图像素。读取时转为 Python 浮点数，不预先截断小数。来源已经量化的精度无法恢复。

图像由 URL 单独下载，`image_sha256` 是原始图像字节的校验值。生产器流式读取已完成的 `train-*.parquet`，不读取下载临时文件，不修改来源文件。eval 集缺少 point，不构造过程 SFT。训练标注由检测及筛选产生，实例集合完整性仍需审核。

## 2. 两阶段生产

运行入口是 `scripts/sft_data/produce_pixmo.sh`。参数在脚本顶部设置，运行时不传实验参数。`SOURCE_ROOT` 指向下载根目录；`PREPARE_ROOT` 应位于 `DATA_DIR` 内的新目录；`LIMIT=3` 为小规模默认，`LIMIT=0` 显式遍历全部训练记录。

`STAGE="prepare"` 下载少量原图并生成离线标注队列，包含原始 point、稳定实例编号、叠加标注图和待填写的审核 JSON。输出目录必须为空，防止覆盖人工审核内容。下载失败、哈希不一致、朝向歧义和 point 冲突写入 `report.jsonl`。哈希不一致的图片保留供诊断，但不生成可用监督。EXIF 旋转记录明确拒绝，待建立可核验的原始 point 朝向映射后处理。

`STAGE="convert"` 读取 `PREPARE_ROOT/images` 的图片与 `AUDIT_ROOT` 指定的已审核记录，通过公共生产器输出完整 `interleaved` 及对应 `visual_only` 候选。缺少审核文件及原图不匹配均产生明确拒绝记录。来源版本采用所在 Parquet 的 SHA256，原始样本编号由分片名称与行号组成。

## 3. 实例框审核接口

自然物体的 point 不足以确定目标可见边界。本实现提供 SAM 3 或几何算法离线结果的导入接口；`data/sft/tools/point_windows.py` 提供规则图形的几何候选及可选本地 SAM 3 Tracker 后端。几何路线需要显式声明 `regular_compact`，自然物体采用 SAM 3 或外部审核结果。实例框生成应遵循 `point_to_window.md`，固定算法与模型版本，并保存提示、候选及审核依据。

每个原始 point 的稳定编号为 `point_0`、`point_1` 等。当前转换器支持一实例一个 point；重复点和不一致总数转入源标注审核。审核 JSON 在自动创建的原始字段之外需要填写：

| 字段 | 要求 |
| --- | --- |
| `source_id`、`image_sha256` | 与当前来源记录及下载图像严格匹配 |
| `method` | `geometry`、`sam3` 或 `geometry_sam3` |
| `config_id` | 对应不可变的离线生成配置，包含适用时的 checkpoint 与代码版本 |
| `instance_boxes_reviewed` | 完成实例语义、可见边界和 point 对应审核后设为 true |
| `complete_instance_set_reviewed` | 完成全部被查询目标的完整性审核后设为 true |
| `instances` | 各项含 `instance_id` 和原图像素 `box: [xmin, ymin, xmax, ymax]` |

人工修正的框需在审核记录增加审核人、依据、修改说明等离线信息，不将算法标签当作质量证明。窗口尚未进行实际 VLM 特征检查时，生产输出继续为 `pending`。原始总数与实例数一致只是一项完整性检查。

## 4. 分组与语言过程

程序先按 bbox 中心纵坐标排序，行内最大中心跨度不超过当前行高度中位数的 0.5 倍，再按行内左边界排序。按连续顺序尝试合并实例，默认每组最多 6 个，联合窗口面积不超过成员 bbox 面积总和的 2 倍。上述常数属于试制配置，需在独立标注开发集校准。当前窗口采用 bbox 联合区域，未额外扩张上下文。

每个分组窗口均与组外实例 bbox 进行保守相交检查。相交时拒绝，避免将其他组中的对象重复计入。复杂重叠场景后续需要联合重分组或按 `new_instances` 规范构造有视觉对应依据的文本。当前实现不自动生成这类轨迹，也未实现非规则布局的扫描带替代方案。

每个窗口后生成当前局部计数及累计计数，最后生成加法表达式与最终数值答案。局部文本只使用当前已观察组的数量，未观察组的数量在最终求和前不进入语言过程。`metadata.counting` 保存实例序列、每步集合和事件关联；`metadata.window_derivations` 保存 point 来源及审核路径。元数据只在监督与审核侧使用。纯视觉版本复用几何，由公共生产器删除语言事件并重映射元数据事件编号。

零目标样本在完整性审核后采用整图观察和零计数。试制阶段应继续检验全局覆盖、停止依据及相同总数的不同窗口数量，不能仅凭几何完整性判定自主搜索能力已得到训练。

## 5. 验证范围与限制

`tests/test_sft_pixmo.py` 检验非正方形图像上的空间重排、可变组大小、局部与累计数量、算术文本、图像哈希错误、重复点以及跨组相交拒绝。测试使用明确的合成 fixture，不能替代真实图像或实际视觉特征审核。

本次真实图片试取中已观察到来源 URL 返回的字节 SHA256 与记录值不同。生产器保持严格校验，相关记录不能成为过程训练数据。后续应获取与来源哈希一致的原始图片；对变化后的图片重新标注需要独立版本和审核流程。当前未发现可直接使用的公共 SAM 3 checkpoint。可选后端已按已安装 Transformers 的 `Sam3TrackerModel`、`Sam3TrackerProcessor` 源码核对接口，但尚未用真实权重执行；真实特征可辨性亦尚未验证。

## 6. 点到框候选生成

`scripts/sft_data/propose_point_windows.sh` 从 prepare 审核队列读取原图及 point，将候选写入新的输出目录，不覆盖来源审核。几何路线使用最近 3 个不同实例点距的中位数，按 0.6、0.8、1.0 倍提出候选尺寸；在背景较均匀、目标实心且紧凑的条件下，以候选边界颜色中位数估计背景，提取 point 所在前景连通域。连通域触及候选边界、包含其他 point、阈值变化不稳定和孤立点均保留明确诊断。

SAM 3 路线只从 `.env` 中 `SAM3_CHECKPOINT` 指向的本地目录加载，不下载模型。图像编码复用，每个实例使用正点和至多 4 个邻近负点，最多增加一次负点复核；保存全部候选 mask、预测质量和提示记录。空 mask、遗漏正点或包含其他已标注实例点的 mask 明确拒绝，候选 bbox 使用最小前景像素至最大前景像素加 1 的半开边界。质量分数只作为审核证据；语义层级和提示复核一致性继续由审核确认。当前一实例一个 point，不支持未经身份确认的多点合并。

候选输出保存在 `candidate_instances`，`instances` 保持为空，两个审核标志保持 false。审核者选择可靠候选、核查实例集合后填写标准 `instances`，再将该目录作为转换阶段的审核输入。配置文件保存生成规则及 SAM checkpoint 文件摘要，配置 ID 由配置内容哈希确定。几何 fixture 检验了连通域细化、半开框、候选写盘与不覆盖来源；mask fixture 检验了单像素框和正负点约束。没有以这些测试声称 SAM 权重推理已通过。

prepare 和候选生成阶段在没有成功记录时以非零状态退出，并保留报告。来源分片与图像哈希采用分块读取，不将整个来源文件一次性载入内存。

SAM 3 权重需通过 [官方模型仓库](https://huggingface.co/facebook/sam3) 的访问授权。本次额外获取配置的尝试中，主站连接超时，镜像返回 HTTP 403；未下载模型权重。生产时提供包含完整 tracker 配置和权重的本地目录，接口会检查架构及加载完整性。
