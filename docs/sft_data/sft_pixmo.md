# PixMo-Count：从实例点标注构造分组计数过程

PixMo-Count 为每个计数目标提供一个 point，但没有实例 bbox 和推理过程。数据生产需要完成三个步骤：确认下载图片与标注对应，为每个实例生成可靠的观察范围，再把不同位置的实例组织为连续的计数过程。自然图像优先使用 SAM 3 生成实例 mask；几何检查筛除明显错误后，教师模型需要检查目标类别、实例边界和遗漏情况。人工抽查放在最终验收阶段。

## 1. 原始数据提供哪些信息

本地数据包含 train、validation 和 test 三个 Parquet 文件。来源说明列出的记录数分别为 36,916、540 和 540。训练记录的字段如下。

| 字段 | 含义及处理方式 |
| --- | --- |
| `image_url` | 原图下载地址。Parquet 不包含图像本身。 |
| `image_sha256` | 来源标注对应的图片字节 SHA256，用于确认下载内容。 |
| `label` | 要统计的目标类别，例如 people。 |
| `count` | 标注的目标总数。 |
| `points` | `x` 和 `y` 两个 float32 数组，表示原图像素坐标。 |

转换程序保留来源的浮点坐标，不预先取整。validation 和 test 没有 point，不用于构造训练过程。原始训练标注也需要检查，point 数量等于 `count` 并不能证明图片中的所有目标均已标注。

## 2. 当前需要解决的质量问题

下面的问题决定了哪些记录可以进入 SFT，不能仅通过 JSON 格式检查判断数据是否合格。

1. **下载图片与来源哈希不一致。** 先前下载的 7 张图片均不匹配；本轮继续下载第 8 至第 19 条记录，12 张图片也全部不匹配。图片可以正常解码，但目前没有证据说明差异仅来自 JPEG 编码，也没有证据确认原始 point 仍然对应相同内容。来源 README 明确规定校验下载字节，改用像素哈希不能解决这一问题。严格转换入口继续拒绝这些记录。
2. **一个 point 不能确定实例边界。** SAM 3 可能分割出整个物体、局部部件或邻近物体。正负点和质量分数能够排除部分错误，但目标语义与可见范围仍需教师判断。
3. **实例集合可能遗漏目标。** 教师需要在不预先看到来源总数的情况下统计目标，并与 point、bbox 和来源答案核对。出现分歧时保留原始证据，不能只调整答案以满足数量一致。
4. **分组窗口可能造成重复计数。** 多个目标在图像中交叠时，一个窗口可能同时包含其他组的目标。当前实现只接受各组可以独立计数的窗口；需要重访和去重的轨迹暂不自动生成。
5. **窗口在模型特征中可能不够清晰。** 原图中的 bbox 正确，并不保证缓存视觉特征保留了计数所需细节。最终验收需要结合实际读取模块检查。

对于哈希变化的图片，可以建立独立图像版本，保存实际字节哈希、来源 URL 和原始哈希，并重新标注目标、point、bbox 与答案。这条路线由 `data/sft/tools/automatic_counting.py` 实现，并通过 `scripts/sft_data/automatic_counting.sh` 启动。严格转换入口继续要求原始哈希匹配。

## 3. 图片准备与实例框生成

运行入口为 `scripts/sft_data/produce_pixmo.sh`，参数集中在脚本顶部。`STAGE="prepare"` 读取已完成的训练 Parquet、下载少量图片并生成标注记录和 point 叠加图。输出目录必须为空，程序不修改来源分片。下载失败、哈希不一致、EXIF 朝向需要转换和 point 冲突分别写入 `report.jsonl`。如果没有成功记录，程序以非零状态退出。需要重新标注变化图片时，显式设置 `ALLOW_IMAGE_REANNOTATION=true`，prepare 会以实际图片哈希建立新记录，并同时保留原始哈希。随后运行 point 候选生成和 automatic counting；不能将这批图片交给要求原始图像一致的 strict convert。

`data/sft/tools/point_windows.py` 负责从 point 提出 bbox。对应入口为 `scripts/sft_data/propose_point_windows.sh`。默认模型名称为 `facebook/sam3`，从 Hugging Face 本地缓存加载；也可以用 `.env` 中的 `SAM3_CHECKPOINT` 指定本地目录。程序支持独立的 `sam3_tracker` checkpoint，以及官方 `sam3_video` checkpoint 中的 tracker。Transformers 提供了后者的子配置和权重加载逻辑，程序另外检查缺失权重和形状不兼容，不随机初始化缺失部分。

SAM 3 对一张图片只编码一次。每个实例以自身 point 为正点，并以最近的至多 3 个其他实例 point 为负点；存在第 4 个邻近实例时，再加入该负点运行一次。程序保存每次提示、全部候选 mask、预测质量和半开边界 bbox。以下检查自动执行：

- mask 必须包含正点，且不得包含任何其他已标注实例的 point。
- 候选质量分数至少为 0.8，保留各次提示中分数最高的有效候选。
- 两次提示的候选 bbox IoU 至少为 0.85；否则记录提示变化导致的不稳定结果。

这些阈值是试制配置，尚未完成独立开发集校准。独立教师重新标注入口允许低于 0.8 的有效 mask 继续送交教师检查，因为 SAM 3 分数不能替代真实框质量判断；它仍保留正负点约束和不同提示的框一致性检查，低分结果不会直接变成审核通过的实例。通过检查的框保存为 `automatic_selection`，状态为 `requires_semantic_verification`。这表示框可以送交教师检查，不表示类别、完整性和计数已经正确。几何路线仅适用于显式声明为规则、紧凑图形的图片；自然物体不使用点间距直接充当实例大小。

## 4. 教师检查与转换接口

教师检查需要围绕三个具体问题展开：每个框是否包含所查询类别的一个实例，框与 point 是否对应同一个实例，全部框是否覆盖图中所有被查询目标。教师结果应绑定图片哈希和框生成配置，保存模型版本、提示与判断依据。建议使用 Qwen3.5-9B；资源受限时可以使用 Qwen3.5-4B。`automatic_counting.py` 依次调用本地教师进行独立计数、每个实例的语义与边界检查、完整轨迹检查。第一次调用只提供原图与类别，不提供来源答案或 point。所有调用的提示、原始响应和完成状态均写入日志。教师独立总数必须与全部实例数量一致，逐实例判断与最后轨迹判断也必须全部通过。

转换接口读取 JSON 中的 `instances`，每个实例包含稳定的 `instance_id` 和原图像素 `box`。`instance_boxes_reviewed` 与 `complete_instance_set_reviewed` 分别表示实例范围和目标集合已经检查；这些字段可以由具备完整证据的自动检查流程填写，并不要求用户逐条手工操作。程序不会仅凭 SAM 3 分数设置这两个字段。人工修改应记录修改者与依据，最终人工抽查与自动检查结果分别保留。

`STAGE="convert"` 读取图片和完成检查的标注，生成 schema 1.1 数据。公共生产器将像素窗口转换为原图长边归一化坐标。尚未完成批次验收的数据继续标记为 `pending`。

## 5. 如何组织多次观察与语言过程

程序先根据 bbox 中心纵坐标分行，再按行内横坐标排列实例。相邻实例可以组成一个观察窗口，默认每组最多 6 个，联合窗口面积不超过成员 bbox 面积之和的 2 倍。每组窗口不得与组外实例框相交。该规则根据空间布局生成不同组大小，可能得到一次观察，也可能得到多次观察；程序不为了增加步骤而重复读取相同区域。

每次观察之后，`interleaved` 轨迹描述当前窗口内的目标数量和累计数量。完成所有分组后，再给出各组数量的加法表达式及最终答案。`metadata.counting` 保存实例顺序、每组成员以及对应事件编号，用于检查遗漏、重复和累计数。`metadata.window_derivations` 保存 point 来源及框生成依据。这些字段留在训练监督与审核侧，不输入模型的推理前缀。

`visual_only` 使用相同窗口顺序，由公共生产器删除自然语言事件并更新事件编号。对于零目标记录，完成目标集合检查后采用整图观察和零计数。当前仅实现 `exclusive` 分组，不支持需要跨窗口实例身份匹配的 `new_instances` 过程。

## 6. 本轮验证范围

本轮已从官方缓存实际加载 SAM 3 tracker 权重，确认无需额外下载独立 tracker checkpoint。CPU 小样本分割用于检查正负点处理、mask 后处理和 bbox 输出。参与诊断的下载图片与来源哈希不同，因此必须通过独立重新标注流程后才能成为 SFT 候选。新版本的 metadata 明确保存原始与实际哈希、原始总数、教师独立答案及检查证据，`annotation_origin` 为 `mixed`。

`tests/test_point_windows.py` 检查点约束、单像素半开框、候选保留和自动选择；`tests/test_sft_pixmo.py` 检查空间分组、累计数、算术过程、源图哈希错误与跨组相交。这些测试使用合成图片，只验证实现约束，不替代真实图片的语义检查。

本轮使用 Qwen3.5-9B 实际检查了 7 条 SAM 候选，3 条通过，分别包含 0、1、2 个目标，导出 6 条双模式记录。逐实例检查单独提供裁剪图片，随后结合整图检查完整覆盖与计数过程。4 条拒绝分别涉及负点提示下分割范围不稳定、独立计数与来源数量不同、裁剪未呈现人物，以及独立计数窗口与其他实例相交。最终展示目录与具体编号见[试制报告](sft_pilot_v2.md)。
