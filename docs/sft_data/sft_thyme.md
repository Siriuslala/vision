# Thyme-SFT 数据构造

Thyme-SFT 保存了教师的自然语言、图像操作代码、工具返回图片和最终答案，可以用于恢复局部观察轨迹。构造过程需要同时检查代码表达的窗口与实际返回图片，并区分正确推理和 self-correction。目标是得到图像依据明确的示范，而不只是将工具调用改写成另一种格式。

## 1. 来源结构

数据存放在 Parquet 分片中，图片以 Base64 字符串列表内嵌保存，不需要另取图片文件。早期检查的四个完成分片位于 `2round` 数据中，编号为 `00003` 至 `00006`，每片包含 2208 条记录；这个数量描述当时读取的文件，不表示当前下载完成度。

| 字段 | 内容 |
| --- | --- |
| `image` | Base64 字符串列表，已检查样本按顺序包含原图和工具返回图片 |
| `question` | 问题、图像占位符、来源图片路径、声明尺寸及教师回答模板 |
| `response` | `<think>` 内的自然语言、`<code>` 图像操作、`<sandbox_output>` 工具返回标记，以及 `<answer>` 最终答案 |

转换后的问题删除来源路径、尺寸声明和工具输出模板，仅保留题目内容。图像路径可以用于辨认上游来源，但不进入模型输入。当前接口支持 GQA 与 COCO `train2017` 图片路径，并映射为 `general_vqa`；其他来源需要检查任务与格式后再增加处理规则。

## 2. 当前发现的问题

Thyme 的主要问题来自工具执行记录与推理内容之间的对应关系。即使最终回答正确，也需要分别确认每次观察和中间判断。

1. **返回图片可能超出代码窗口。** 早期样本中，一次裁剪经代码放大后应为 108 × 136，保存的工具图片却是 128 × 136，并包含额外横向上下文。不能仅按 resize 解释这个差异。
2. **来源轨迹可能包含错误纠正。** 某些样本先读取错误区域，随后重新定位。它们适合学习恢复，但需要与没有错误的基本轨迹分开。
3. **语言中的纠错描述未必对应几何变化。** 个别“修正后”窗口与前一次相同，因此分类需要结合图片和中间判断，不能只匹配关键词。
4. **工具语言不一定适合作为训练文本。** 自然语言可能引用文件、代码或工具能力，需要改写为基于当前视觉信息的观察和判断，并重新检查语义。
5. **格式恢复不证明答案正确。** 读取位置合法、返回图片相近，并不意味着属性判断或最终答案具有充分依据。

## 3. 从代码恢复窗口

转换器使用 Python AST 解释受支持的图像操作，不执行来源 Python。当前支持数值赋值、基础算术、可解析的路径字符串、PIL `crop`、NumPy 二维 slicing 和 `resize`。每个代码块需要对应一张已保存的裁剪图片及紧随其后的工具返回标记。

图像变量同时保存原图范围与当前尺寸，因此对缩放图片继续裁剪时，可以将窗口恢复到原图坐标。原图是区域 0；在已经展示的窗口中继续观察时，使用对应 `reference_region_id`。只在代码中产生、没有向教师展示的中间图片不新增观察事件。

PIL 与 NumPy 的整数边界语义分别保留。窗口越界、未知表达式、旋转、增强、外部检测器或不能确定的工具输出进入拒绝记录。转换后的 `visual_read` 保留真实顺序，`<answer>` 单独作为最终答案；源码不进入 trajectory。

## 4. 正确轨迹与 self-correction

来源轨迹通过图像核对后，再由教师检查每一步是否读取了题目所需信息，以及中间判断是否正确。没有已确认错误的过程归入 `normal`；存在明确错误并随后恢复的过程归入 `self_correction`。暂时无法确定的过程不应被当作基本正确示范。

对于有价值的纠错样本，可以另外生成不包含错误的版本。教师从原图和问题重新规划必要观察，或者以已经确认的正确观察作为依据补全连贯过程。生成后独立核对答案与每步判断，不能仅删除错误窗口，因为后续文本可能仍包含“刚才的位置错误”等上下文依赖。

同一题目的两种轨迹版本共享来源与数据划分，输出记录具有不同身份，并分别存储。正常版本优先完善 `interleaved`，再按公共规则构造删除文字的 `visual_only`。纠错版本先保留 `interleaved`，以免删除语言后仍将不可见的错误判断当作纠错监督。两次观察可以属于正常的多区域推理，也可以属于一次失败后的恢复；读取数量与轨迹类别分别记录。

## 5. 图片核对与验证

现有图片核对将恢复的窗口从原图裁出，与工具返回图片分别缩放到 32 × 32，再计算 RGB 平均绝对误差。阈值为 20，结果保存在 `metadata.preview_checks`。它用于发现明显不匹配，不能证明两张图片逐像素等价，也不能替代教师语义检查和最终抽检。

早期试制检查八条来源记录，两条通过静态解释与图片差异筛查，六条因返回图片不匹配拒绝。这个结果表明需要检查工具记录的对应关系，不能作为 Thyme 总体合格率。本轮跨五个完成分片分别检查 20 条，共 100 条题目，其中 41 条通过两次裁剪的图片重放检查，59 条来源过程未通过。全部题目仍可进入从原图重新生成的流程。第 12 个分片还包含不依赖局部观察的常识延展问题，需要在语义筛选时区分。后续自动通过数量与轨迹分类以实际运行报告为准。

测试覆盖嵌套裁剪、resize 坐标恢复、区域引用、未知操作拒绝、语言与答案边界及错误返回图片。来源过程转换入口为 `scripts/sft_data/produce_thyme.sh`，自动生成与语义检查入口为 `scripts/sft_data/produce_automatic.sh`（选择 `DATASET="thyme"`，清空 `SUBSETS`），输出组织、教师模型与抽检要求见[公共生产说明](sft_production.md)。

自动入口还会重新表达来源语言，删除文件、代码标题和工具操作说明。重写只修改语言事件，观察框与先后顺序由程序保留。通过检查的来源原文仍存于 metadata，便于核对重写是否保留了真实错误与恢复过程。本轮示例见[试制报告](sft_pilot_v2.md)。
