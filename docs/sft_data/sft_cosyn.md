# CoSyn-400K 数据构造

CoSyn 提供合成图像、问题、答案和 explanation，适合构造图表、表格及文档读取任务。它没有直接给出本项目所需的观察窗口和事件顺序，因此需要教师从实际图片中补充这些信息。构造的核心是确认图片能够支持题目，再建立观察与推理过程；图形生成时使用的数据不能代替图片证据。

## 1. 数据结构

数据按领域存放在不同目录中，每个 Parquet 文件包含多张图片。`image` 内嵌图片 bytes，可以直接解码，不需要额外下载图片。一张图片对应多组问题、explanation 和答案。

| 字段 | 含义与用途 |
| --- | --- |
| `id` | 图像编号，通常包含生成 pipeline、图形类型及序号 |
| `image` | 包含 `bytes` 和 `path`；转换读取内嵌 bytes |
| `qa_pairs` | `question`、`explanation`、`answer` 三个平行列表，或对应的记录列表；相同位置组成一组问答 |
| `metadata` | 图形类型 `figure_type`、人物设定 `persona`、主题 `topic` 等生成信息 |
| `data` | 图形生成所用的数据，常以 CSV 字符串保存 |
| `code` | 图形生成代码，用于离线分析图片的呈现方式 |

2026-09-15 的本地文件检查找到七个完成的 chart 分片，尚未找到其他领域的完成分片。数据集还包括 chemical、circuit、diagram、document、graphic、math、music、nutrition 和 table 等领域；这些领域需要在相应下载完成后分别检查字段和任务内容。文件数量只是下载期间的状态，不代表数据集总量。

## 2. 当前发现的问题

CoSyn 的主要质量问题是原始问题、explanation 与静态图片之间可能不一致。此类问题应在生成轨迹之前筛查，避免教师根据问题中的暗示补全图片中没有的信息。

1. **精确数值可能没有显示。** 部分图形将数值写入交互式 hover 信息，而训练图片是静态 PNG。explanation 引用这些数值时，即使计算正确，也不足以证明题目可以从图片回答。
2. **来源计算可能有误。** 在已抽读的折线图问题中，explanation 的求和与平均数需要重新核算。来源答案不能作为自动通过检查的依据。
3. **问题表述可能存在歧义。** “增长率更高”可能指绝对增量，也可能指相对增幅；若题目没有说明而两种解释导致不同答案，需要拒绝或单独修订题目并保留修改记录。
4. **多问题集中在同一张图片上。** 连续检查前十个问题可能只覆盖一张图，无法反映不同图形的情况。小样本应同时限制每图问题数，并覆盖不同图形和题型。

## 3. 轨迹构造

转换器先展开每张图的问答列表，再由教师生成观察过程。标题识别通常只需要一次局部读取；比较不同类别、不同年份或两条曲线的问题，可以依次读取相关区域后形成判断。窗口应保留解释数值所需的轴、图例、单位或行列标题，不能只截出缺少语义的图形片段。

多次读取优先选择具有两个或多个独立证据位置的问题。例如，比较两个城市同一年的人口，需要分别确认城市标识与相应年份的数据；表格金额相加需要读取两个项目及价格。若整块信息在一次窗口中已清晰可辨，可以保留一次读取，不为了增加观察次数拆分窗口。

教师根据图像和问题独立生成最终回答及 `interleaved` 过程，随后检查每一步的可见事实、计算和答案。原始 explanation 保存在离线 `metadata.source_explanation`，不会直接复制到 `trajectory`。通过检查的过程可以生成删除语言事件的 `visual_only` 版本；两种模式保留相同问题、最终答案和窗口顺序。

## 4. 字段转换与失败处理

`data/sft/datasets/cosyn.py` 中，`iter_tasks` 负责读取来源问题，`iter_candidates` 负责关联补充标注。每个问题的来源编号包含领域、图像 `id` 和问答序号；同一张图的全部问题共享 `group_id`。标注使用内容相关的 `source_key`，绑定问题、答案、来源编号与图像 bytes。

任务映射目前将 chart、table、document 分别对应 `chart_qa`、`table_qa`、`document_qa`；nutrition 使用 `document_qa`，其余已支持领域使用 `general_vqa`。这是转换器的来源级映射，后续应通过实际样本检查细化任务分类。

平行列表长度不一致、图片缺失、问题或答案无效时，转换器记录拒绝原因。缺少窗口标注的题目保留来源身份，等待教师处理；不能以一个任意窗口作为成功转换。生成代码只用于离线核查，训练输入不包含底层 CSV、代码或来源 explanation。

## 5. 运行与验证

运行入口为 `scripts/sft_data/produce_cosyn.sh`，教师入口为 `scripts/sft_data/propose_sft_regions.sh`。来源目录、输出目录、标注文件和样本上限均在脚本顶部配置。试制结果使用独立目录，并按[公共生产说明](sft_production.md)接入 viewer。

格式测试覆盖问答列表对应、问题数量限制、缺失标注、标注内容绑定、非方形图片坐标以及双模式构造。实际质量检查还需要查看静态图片和逐步过程；格式通过不说明数值可见，也不说明来源答案正确。本地 chart 的试制结论不能外推到尚未读取的 document 或 table 数据。

本地教师的自动生成与检查使用 `scripts/sft_data/produce_automatic.sh`。本轮实际展示的例子、没有通过的情况及解释见[试制报告](sft_pilot_v2.md)。
