# 一般视觉推理任务的 SFT 数据生产

本流程将已有视觉问答数据转化为带有局部观察过程的 SFT 数据，重点是一般视觉推理任务。每条示范需要明确问题、每次观察的位置、观察后的自然语言判断以及最终答案，并符合[数据格式 1.1](../visual_reasoning_data_format.md)。数据构造优先完成 `interleaved` 轨迹，再从合格轨迹生成删除 `reasoning_text` 的 `visual_only` 版本。

数据生产由来源读取、轨迹构造、自动质量检查和最终抽检组成。本地教师负责可以自动完成的筛选、补充标注和语义检查；人工检查集中在最后，对自动处理后的样本进行抽检，并分析自动检查无法判断的问题。教师提出的结果与通过质量检查的结果分别保存，便于定位错误来自原始数据、轨迹生成还是质量判断。

## 1. 数据来源与主要问题

五个数据集提供的信息不同，因此不能共用一种轨迹生成方法。Visual-CoT 和 Thyme 已经包含区域或工具操作信息，可以先恢复这些信息；CoSyn 和 LLaVA 主要提供图像与问答，需要教师补充观察过程；PixMo 的点坐标需要先转换为实例框。

| 数据来源 | 已有信息 | 构造方法 | 需要优先解决的问题 |
| --- | --- | --- | --- |
| Visual-CoT | 问题、答案、bbox；部分 GQA 数据还有自然语言 `thought` | 恢复原图坐标，检查区域；在信息充分时构造观察和语言事件 | 多个 bbox 没有明确的先后顺序；部分来源没有自然语言过程；个别框越界 |
| Thyme-SFT | 问题、答案、自然语言、图像操作代码及工具返回图片 | 恢复实际观察窗口与顺序，分别保留正确轨迹和 self-correction 轨迹 | 工具返回图片与代码声明的范围可能不一致；部分轨迹包含首次错误读取 |
| PixMo-Count | 图片 URL、哈希、实例点、类别和数量 | point → 实例框 → 分组观察 → 局部计数与累计 | 点不表示物体范围；需要确认分割结果、类别和实例集合完整性 |
| CoSyn-400K | 图像、多组问题与答案、explanation、生成数据和代码 | 从图片独立生成观察过程，再检查回答与来源答案 | explanation 可能使用静态图片未显示的数值；原始计算和题目表述也可能有误 |
| LLaVA-OneVision | 多来源图像和对话 | 按子集解析问题及最终答案，由教师补充观察与推理 | 子集格式和任务差异大；长回答的答案边界、多轮依赖和错误标签需要分别处理 |

每个来源的详细字段、转换步骤及已知问题分别见 [Visual-CoT](sft_visual_cot.md)、[Thyme](sft_thyme.md)、[PixMo](sft_pixmo.md)、[CoSyn](sft_cosyn.md)和 [LLaVA](sft_llava.md)。合成迷宫、连线、找不同和拼图属于另一条数据构造路线，不在本流程中展开。

## 2. 来源读取与文件组织

来源读取的目标是取得可复现的图像和标注，同时兼容尚未完成的下载。Parquet 内嵌图片直接解码；Visual-CoT 的连续 tar 分片按顺序读取，将所需图片提取到独立目录。程序只处理已经完成的文件，不读取下载器的临时文件，也不覆盖下载源。新完成的文件在下一次运行时纳入。

读取异常需要保留明确原因。无法打开或读取期间发生变化的完整分片使本次运行报错；单个样本缺图、尺寸不一致或字段无效时，记录来源编号与拒绝原因。来源代码仅用于解释已经保存的操作或核对图形生成信息，不直接执行其中的任意 Python 或网页脚本。

项目按职责组织实现：`data/sft/datasets/` 保存各数据集转换器，`data/sft/core/` 保存公共格式与标注逻辑，`data/sft/tools/` 保存生产和检查工具，`data/sft/viewer/` 保存交互可视化。Bash 入口位于 `scripts/sft_data/`，本文档及来源说明位于 `docs/sft_data/`。运行参数在对应 Bash 脚本顶部设置，环境仍使用 README 中的 Python 3.12 与 `uv run --frozen`。

小样本试制的图像、JSONL 和检查报告统一放在用户指定的 `/archive/public/tmp` 下，并为每次试制建立独立目录。来源目录和模型缓存路径通过私有 `.env` 配置。可视化工具按 JSONL 文件与图片根目录加载结果，具体配置见 [viewer 说明](viewer.md)。

## 3. 轨迹构造与课程分组

轨迹首先需要回答“完成这道题需要读取哪些信息”。直接识别整图即可作答的问题可以没有额外窗口；局部文字或属性识别通常读取一次；比较两个区域、依据参照物寻找目标或汇总不同表格行的信息，可能需要多次读取。教师应按证据需求选择窗口，不能通过重复读取同一区域或将连续区域任意切开来增加步骤。

生产结果按实际 `visual_read` 数量分为 `zero_read`、`one_read` 和 `multi_read` 三组，分别对应零次、一次和至少两次额外读取。这个分组用于训练课程和样本统计。读取次数不能单独决定难度：文字密度、物体遮挡、区域之间的关系以及最终计算也会影响任务难度。

轨迹是否包含错误纠正单独分类。`normal` 表示没有已确认的错误读取或错误中间判断；`self_correction` 表示轨迹先出现错误，随后识别并修正。两个类别分别存储。同一道题可以具有两个版本，但正确版本必须独立检查，不能简单删除错误段后保留依赖错误上下文的句子。来源轨迹中的“再次查看”或“修正”等词语只能作为待检查线索，不能据此直接确定类别。

`interleaved` 的自然语言需要明确写出每次观察获得了什么信息，以及这些信息如何支持后续步骤。已有 `thought` 或 explanation 必须检查图像依据和事件顺序；缺少自然语言过程时，交由教师生成。完成质量检查后，删除 `reasoning_text` 得到 `visual_only`，同时重新编号事件并更新相关引用。计数数据还需更新 `metadata.counting` 中指向事件的字段，具体规则见[计数轨迹方案](../counting_trajectories.md)。

## 4. 本地教师的生成与检查

本地教师默认使用 `Qwen3.5-9B`，GPU 资源受限时使用 `Qwen3.5-4B`。模型规模、速度和实际通过率应在同一批题目上比较后再决定大规模配置。历史 Qwen3-VL 试制保留其真实模型记录，不计作 Qwen3.5 的验证结果。SAM 3 负责点提示分割，其输出仍需检查是否覆盖目标实例。

自动试制入口为 `scripts/sft_data/produce_automatic.sh`，支持 LLaVA、CoSyn、Thyme 和 Visual-CoT。生成和检查共享 `data/sft/tools/local_teacher.py`，每次调用使用新的上下文，并保存完整提示与回答。自动处理包括以下步骤：

1. **筛选题目。** 判断题目是否可以从当前图片回答，识别需要的视觉信息，并检查是否适合当前支持的任务类型。没有图像依据的精确数值、缺失的对话上下文或无法确认的标签进入拒绝或待检查记录。
2. **生成轨迹。** 根据图片和问题生成窗口、观察结论及最终回答。生成时不提供来源答案，以便保留独立作答结果。对于存在可靠区域标注的来源，可以利用这些标注约束窗口，但仍需说明各次读取的用途。
3. **检查观察证据。** 单独提供实际裁剪图片，不提供整张原图、生成答案或推理文字，让教师描述每个窗口并重新作答。正常轨迹要求所有窗口可用，纠错轨迹允许前面的窗口选择错误，但最后的观察必须可用。缺少文字、目标不完整或无法回答的过程被拒绝。
4. **检查完整过程。** 在新的上下文中提供原图、实际窗口和候选轨迹，核对事实、推理、重复读取及纠错分类。答案先按规范化文本比较；开放式文本存在措辞差异时，另用一次文本判断检查是否表达相同含义。答案存在实质差异时保留双方结果，不自动替换来源答案。

失败的正常轨迹最多再生成一次。修正提示可以包含此前的候选和裁剪检查结果，但不提供来源答案。来源编号与每次失败原因仍保留在日志中；重试后仍未通过的题目不会进入候选文件。

纠错过程先由教师清理来源中的文件、代码和工具措辞，程序保留每次读取的窗口及顺序，再重新检查。纠错分类要求指出错误区域或错误事实；先定位正确参照物再观察另一物体属于正常推理。当前纠错示例保留 `interleaved`，正常示例在删除语言不丢失必要输入证据时同时导出 `visual_only`。算术和逻辑推导本身不构成保留语言的必要条件，实际内部推理能力仍需训练后验证。

额外的模型调用能够提供检查，但同一模型可能重复相同错误。因此，质量报告需要记录检查模型、输入图片与窗口、判定理由及不确定项。不能把一次生成成功或两次回答相同视为图像依据充分的证明。

窗口生成默认采用候选区域选择。表格通过水平边框或文字行确定候选范围；图表采用保留类别标签和坐标轴的较大窗口；普通图片提供相互重叠的网格区域。Visual-CoT 优先使用来源标注框，Thyme 可以将能够重放的来源窗口加入候选。教师看到原图及带有明确编号的候选区域预览，选择区域编号并组织读取顺序。预览只用于离线构造，模型训练记录仍使用原图坐标。候选窗口覆盖范围由程序确定，因此不会因模型输出不准确的坐标截断表格文字。网格范围较粗，可能不适合密集物体或极小文字；没有合适候选时应拒绝或补充区域生成方法。`--window-method coordinates` 保留直接预测坐标的实验方式，但同样接受实际裁剪检查；`direct` 用于验证不需要额外窗口的对照样本。

教师接口中的坐标与训练格式分别处理。若提示要求横纵轴各用 0–1000 刻度，解析器先按原图宽高恢复像素坐标；公共构造器再按原图长边归一化。自动生成记录通过来源编号、版本、原图 SHA256 与 variant 区分。导入外部补充标注时使用 `source_key` 关联来源编号、问题、答案和图像内容，防止图片或题目变化后使用旧标注。

补充标注文件使用 JSONL，每条记录描述一个来源问题的轨迹。以下字段属于离线标注接口，不直接作为模型输入：

| 字段 | 含义 |
| --- | --- |
| `source_key` | 由来源编号、问题、答案和图像 bytes 计算的内容标识 |
| `events` | 按执行顺序保存 `visual_read` 和 `reasoning_text`；观察使用像素 `box` 与 `reference_region_id` |
| `status` | `proposed` 表示待检查的提议，`reviewed` 表示标注已完成检查，`rejected` 表示拒绝；具体检查来源仍需记录 |
| `reviewer` | 标注检查者的身份；自动检查应明确记录教师模型，不能使用虚构人工身份 |
| `reason` | 拒绝标注的具体原因 |
| `visual_only_safe`、`visual_only_basis` | 是否允许删除语言生成配对版本，以及相应检查依据 |

`reviewed` 是补充标注的检查状态，与标准记录的 `quality.status` 不同。即使标注已通过教师检查，输出仍可保持 `pending`，等待训练条件检查和最终抽检。

## 5. 公共格式与质量检查

公共构造器负责坐标、事件和来源字段的一致性。转换器内部窗口使用原图像素 `xyxy`，标准数据保存长边归一化的 `center` 和完整 `size`。图像保存时记录 SHA256 与解码尺寸；存在 EXIF 朝向变换时，需要明确映射标注，不能在不知道坐标来源的情况下旋转图片。

每次运行保留 `candidates.jsonl`、`rejections.jsonl` 和 `manifest.json`；自动入口另存 `teacher_calls.jsonl`，记录生成、裁剪检查、答案比较与完整过程检查的原始回答。自动通过的记录同时按 `normal`／`self_correction`、`zero_read`／`one_read`／`multi_read` 和 reasoning mode 分别写入文件。候选文件保存满足结构要求的样本；拒绝文件说明未生成或未通过检查的原因；manifest 记录输入文件、配置、结果数量和运行状态。`metadata.automatic_quality.passed=true` 表示通过当前自动检查，具体判定和模型信息随记录保存。同一模型重复判断仍可能出现共同错误，实际视觉特征下的可读性也未在此步骤验证。`quality.status=pending` 表示尚未完成最终验收，不能因为已生成窗口或通过 JSON 校验就改为正式训练状态。

质量检查涵盖四个层面，并分别记录结果：

| 检查层面 | 需要确认的内容 |
| --- | --- |
| 文件与格式 | 图片可解码，来源可追溯，字段与事件合法，窗口不越界，引用指向已有区域 |
| 图像与答案 | 当前图片能够支持题目，来源答案与可见内容一致，数值和选项没有提取错误 |
| 过程 | 窗口覆盖证据，文字判断有依据，多次读取具有实际用途，正确与纠错轨迹分类合理 |
| 训练条件 | 使用最终视觉特征配置仍能辨认关键内容，数据划分与外部评测隔离，批次抽检完成 |

所有来源共用 `split_registry.sqlite`，检查图像 SHA256 和 `group_id` 的划分一致性。同图不同问题、不同轨迹和两种 reasoning mode 应归入同一划分。这个检查不能识别所有重新压缩图片和结构变体，因此批次验收仍需要记录近重复检查及外部测试重叠检查。

人工参与位于自动处理之后。最终抽检通过 viewer 查看原图、窗口和完整过程；发现系统性问题时修改生成或检查规则，再重新处理受影响数据。当前入库工具要求接受决定绑定候选内容哈希，并通过批次报告记录抽检范围、特征配置和来源重叠检查。自动语义检查与最终训练验收应保持不同状态，避免把模型判断误记为人工确认。

## 6. 试制结果的解释

小样本试制用于发现数据结构和方法问题，结果应按“检查了多少来源题目、生成多少条轨迹、拒绝原因、检查方式”记录。一个来源问题可以生成多条轨迹和两种 reasoning mode，因此来源题目数与输出记录数需要分别报告。抽样应覆盖不同图像、子集和任务类型，不能只取同一张图片的多个问题。

早期试制已经发现 Visual-CoT 缺少自然语言过程、Thyme 工具返回图片不匹配、CoSyn 静态图像缺少数值依据以及 LLaVA 来源答案错误等问题。这些现象构成后续自动检查的重点。具体试制数量和当前可浏览文件以运行报告及 viewer 配置为准；极少量样本的通过情况不用于估计全量合格率。

本轮试制的题目范围、最终展示文件和排除原因见[试制报告](sft_pilot_v2.md)。自动教师入口当前按小批次串行运行，尚未进行全量吞吐测试。`LIMIT` 限制进入教师流程的题目数，`SCAN_LIMIT` 限制查找题目的来源范围，Thyme 可用 `PER_SHARD_LIMIT` 跨分片抽样；指定来源编号可复查同一批问题。
