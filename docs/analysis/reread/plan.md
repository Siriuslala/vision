# 局部重读

本问题属于[视觉表征研究计划](../plan.md)的问题 5，对应项目的方向二。方向二设想在推理时由原 LLM 选择图像窗口，从缓存的视觉特征中取出该窗口的局部特征并再次送入 LLM。在训练任何窗口选择模块之前，本问题以真值给定的 oracle 窗口检验这一操作的前提：重新输入局部区域能否改善回答，缓存特征是否足够，以及重读的 visual token 应当携带什么 position IDs。

## 1. 研究问题与动机

前期实验显示，局部改动可以在配对特征差分中定位，但在密集网格中这一定位明显减弱，Qwen3.5-9B 在 BabyVision 找不同上几乎全部失败。若失败的原因是细节在大图中被稀释，或单个实例分到的 token 太少，则在推理时重新输入目标区域可能弥补细节感知的不足。方向二的方案依赖三个尚未验证的假设，本问题依次检验：

1. **重读有用。** 在模型已经看过整图的条件下，再输入一次目标区域的视觉信息，能否提高细粒度任务的准确率。
2. **缓存特征足够。** 整图编码得到的 merger 输出中，目标区域的 visual tokens 是否保留了足够的细节；还是需要将该区域裁剪后重新经过 ViT 编码。
3. **位置编排有效。** 重读的 visual tokens 沿用其在原图中的行列位置，与按一张新图像从零编排相比，哪一种更有利于实例对应与原图坐标的输出。

本问题当前只包含实验 5.1（zoom oracle）。oracle 窗口给出局部重读收益的上界，模型能否自主选择窗口留待方向二的方法研究。

## 2. 总体设计

实验 5.1 在相同图像与问题上比较多种视觉输入条件。各条件在原图输入之后附加不同来源的局部视觉信息，或改变整图的分辨率，并以“额外输入非目标区域”作为对照。条件之间的成对比较对应上述三个假设：

| 比较 | 检验的假设 |
| --- | --- |
| 裁剪重编码对原图基线；整图放大对原图基线 | 增加目标区域的分辨率与 token 数能否改善回答 |
| 缓存重读对同分辨率的裁剪重编码 | 整图上下文中编码的缓存特征是否保留了局部细节 |
| 缓存重读（原坐标）对缓存重读（新坐标） | 原图 position IDs 对实例对应与坐标输出的作用 |
| 目标区域重读对随机区域重读 | 收益是否来自目标区域的信息，并排除额外 token 与额外计算的一般效应 |

主模型为 Qwen3.5-9B，thinking off；Qwen3-VL-8B-Instruct 作为对照模型，以检验结论是否依赖 DeepStack 与 decoder 结构。

## 3. 符号与输入构造

### 3.1 符号

| 符号 | 形状 | 含义 |
| --- | --- | --- |
| $I$ | 图像 | 原始输入图像 |
| $H, W$ | 标量 | 原图经 processor 后 merged 网格的行数与列数，每个 visual token 对应 32×32 pixels |
| $v_{r,c}$ | $d$ 维 | 原图 merger 输出中第 $r$ 行、第 $c$ 列的 visual token，$r, c$ 以 0 起编号 |
| $d$ | 标量 | LLM hidden size，Qwen3.5-9B 为 4096 |
| $R$ | 下标集合 | oracle 区域，$R = \{(r, c) : r_0 \le r < r_1,\ c_0 \le c < c_1\}$ |
| $h_R, w_R$ | 标量 | oracle 区域的行数与列数，$h_R = r_1 - r_0$，$w_R = c_1 - c_0$ |
| $K$ | 标量 | oracle 区域内的 visual token 数，$K = h_R w_R$ |
| $(x_1, y_1, x_2, y_2)$ | 4 个标量 | oracle 区域在原图中的 0–1000 归一化坐标，横轴向右，纵轴向下 |
| $\boldsymbol{p} = (p^t, p^h, p^w)$ | 3 个整数 | 一个 token 的 MRoPE position IDs，分别对应时间、行、列三个轴 |
| $s_1, s_2$ | 整数 | 原图 visual tokens 与第二段视觉 token 的起始位置 |

oracle 区域的边界与 visual token 边界对齐。合成刺激的实例单元为 64 pixels，恰好覆盖 2×2 个 visual tokens，因此以实例单元为单位定义的区域天然对齐；RefCOCO 的区域在 processor 缩放后的图像上向外取整到 32-pixel 边界。

### 3.2 序列结构与 position IDs

所有含第二段视觉输入的条件采用相同的序列结构：原图 visual tokens，第二段视觉 token，可选的区域提示，问题文本。Qwen3.5 对图像 token 的默认编排为

$$
\boldsymbol{p}(v_{r,c}) = (s_1,\ s_1 + r,\ s_1 + c),
$$

即同一图像的全部 token 共享时间轴位置 $s_1$，行、列两轴分别加上 token 所在的行号与列号。图像之后的文本从全部已用位置的最大值加 1 开始逐个递增，三个轴取相同的值。第二段视觉 token 之前的分隔 token 按此规则编排，第二段的起始位置记为 $s_2$。

这一编排使 attention 中两个 token 之间的旋转角差只依赖它们在各轴上的位置差。因此，第二段 token 的行、列位置与原图 token 是否相同，决定了 attention 能否通过位置分量把重读 token 与原图中同一位置的 token 联系起来。在 Qwen3.5 中，position IDs 只进入 gated full attention 层的 MRoPE，Gated DeltaNet 层只感知序列顺序；Qwen3-VL 的全部 decoder 层均使用 MRoPE。

### 3.3 条件定义

| 条件 | 第二段视觉输入 | 第二段的 position IDs | 额外 token 数 |
| --- | --- | --- | ---: |
| (a) 原图基线 | 无 | 无 | 0 |
| (b) 整图放大 | 无，原图边长放大 2 倍后作为唯一图像输入 | 默认编排 | $3HW$ |
| (c1) 裁剪重编码，1 倍 | 将区域从原图裁出，不缩放，作为第二张图像经过 ViT 与 merger | 新图像默认编排 | $K$ |
| (c2) 裁剪重编码，2 倍 | 将区域裁出后边长放大 2 倍，作为第二张图像经过 ViT 与 merger | 新图像默认编排 | $4K$ |
| (d) 缓存重读，原坐标 | $\{v_{r,c} : (r, c) \in R\}$，按行优先顺序排列 | $(s_2,\ s_1 + r,\ s_1 + c)$ | $K$ |
| (e) 缓存重读，新坐标 | 与 (d) 相同 | $(s_2,\ s_2 + r - r_0,\ s_2 + c - c_0)$ | $K$ |
| (f-c) 随机区域裁剪重编码 | 与 (c2) 相同的操作，作用于等大的非目标区域 | 新图像默认编排 | $4K$ |
| (f-d) 随机区域缓存重读 | 与 (d) 相同的操作，作用于等大的非目标区域 | 与 (d) 相同的规则 | $K$ |
| (g) 特征来源扫描 | 区域内 ViT 第 $\ell$ 层特征经 merger 投影后的 token，$\ell$ 取多个深度，定义见第 3.4 节 | 与 (d) 相同的规则 | $K$ |

各条件的设计考虑如下：

1. **(b)** 只提高整图分辨率，不提供任何区域信息，用于区分“分辨率不足”与“需要聚焦于局部区域”。放大后 processor 的最大像素限制相应提高，20×20 网格放大后约为 6400 个 visual tokens。
2. **(c1) 与 (c2)** 均重新经过 ViT 编码。(c1) 与 (d) 的 token 数与分辨率相同，二者只在编码时的上下文范围上不同：(c1) 的 ViT attention 只覆盖区域内部，(d) 的 token 在整图上下文中编码。(c2) 在 (c1) 的基础上提高分辨率，二者之差反映分辨率的作用。
3. **(d)** 的行、列位置与原图中同一位置的 token 完全相同，时间轴取新的起点 $s_2$，以表示该段输入在序列中晚于原图出现。这一编排与视频输入中各帧共享空间位置、在时间轴上递增的做法相似，使重读 token 在行、列分量上与原图对应 token 对齐。
4. **(e)** 将同一组 token 视为一张 $h_R \times w_R$ 的新图像，与 (d) 只在 position IDs 上不同，二者之差直接反映原图坐标的作用。
5. **(f-c) 与 (f-d)** 的随机区域与目标区域等大、互不重叠，位置用固定随机种子抽样，分别控制两条重读路径中额外 token 与额外计算的一般效应。
6. **(g)** 扫描重读特征的来源深度，具体条件见第 3.4 节。

所有含第二段视觉输入的条件，分别在有无区域提示两种情况下运行。区域提示为“The second image is a zoomed view of region (x1, y1, x2, y2) of the first image.”，其中四个数值为 oracle 区域的 0–1000 坐标。区域提示把第二段输入与原图的对应关系以文本方式给出，比较有无提示可以判断模型能否仅凭视觉输入建立这一对应。

对 Qwen3-VL 运行 (d)、(e)、(f-d) 时，第二段 token 位置同样加入对应区域的 DeepStack 特征，visual_pos_masks 需要包含第二段位置；若通过 inputs_embeds 调用而不显式传入 deepstack_visual_embeds，DeepStack 会被静默丢弃。

### 3.4 重读特征的来源

条件 (d) 重读的是 ViT 末层经主路径 merger 投影后的 visual tokens。实验 2.1 显示，局部改动的配对响应在 ViT 浅层与中层最为集中，DeepStack 也正是从 ViT 多个深度抽取特征注入 LLM，因此重读特征的来源深度是需要系统比较的因素。条件 (g) 在保持区域、序列结构与 position IDs 规则不变的前提下，只改变重读 token 的特征来源。

设 $X^{(\ell)}$ 为 ViT 第 $\ell$ 层（从 1 开始）输出的 patch 特征，形状为 $N_p \times 1152$，$N_p$ 为图像的 patch 数；$M_0$ 为主路径 merger。对 Qwen3.5-9B，扫描以下来源：

| 记号 | 重读 token | 说明 |
| --- | --- | --- |
| (g-$\ell$) | $M_0\left(X^{(\ell)}\right)$ 中区域内的 token，$\ell \in \{3, 9, 17, 25\}$ | 主路径 merger 只在 ViT 末层特征上训练，较浅层的投影属于分布外输入；第 9、17、25 层与 Qwen3-VL-8B 的 DeepStack 抽取层（block 索引 8、16、24，0 起）位置相同 |
| (g-27) | $M_0\left(X^{(27)}\right)$ 中区域内的 token | 与条件 (d) 相同，作为扫描的末端参照 |
| (g-cat) | 同一区域依次重读 (g-9)、(g-17) 与 (g-27) 三段 token，三段使用相同的行、列 position IDs，时间轴依次递增 | 同时提供多个深度的特征，由模型的 attention 选择使用哪一段 |

对 Qwen3-VL-8B-Instruct，ViT 中间层特征有经过训练的 DeepStack merger $M_k$，因此扫描以下来源。其中 $L_v = 27$ 为 ViT 层数，$l_k$ 为第 $k$ 个 DeepStack 抽取层（按本节的 1 起编号为第 9、17、25 层），$D_k = M_k\left(X^{(l_k)}\right)$ 为其 DeepStack 特征。[多层视觉特征注入](../deepstack/plan.md)第 4 节的上标沿用配置中的 0 起索引，与本节相差 1。

| 记号 | 重读 token | 说明 |
| --- | --- | --- |
| (g-VL-$k$) | $M_k\left(X^{(l_k)}\right)$ 中区域内的 token，$k = 1, 2, 3$ | 以 DeepStack 特征单独作为输入 embedding，训练中该特征只以残差相加方式使用 |
| (g-VL-inj) | 主路径 token $M_0\left(X^{(L_v)}\right)$，并在 decoder 第 1–3 层之后于第二段位置加入对应的 $D_k$ | 与训练时的注入方式一致，分布外程度最低；条件 (d) 在 Qwen3-VL 上即采用这一形式 |
| (g-VL-off) | 主路径 token，第二段位置不加入 $D_k$ | 与 (g-VL-inj) 对照，测量注入特征在重读中的作用 |

此外，深度扫描同时作用于重新编码的局部图像：对条件 (c1) 的裁剪图像也提取 ViT 第 9、17、25 层特征并按同一方式投影，记为 (c1-$\ell$)。比较 (g-$\ell$) 与 (c1-$\ell$) 可以在每个深度上区分“整图上下文中编码”与“局部单独编码”的差别，从而判断细节丢失发生在 ViT 的哪一段深度。

扫描只在主要任务（T3 与 T5）的一个网格规模上运行全部来源，其余任务只运行在主要任务上表现最好的两个来源，以控制计算量。由于浅层投影属于分布外输入，(g-$\ell$) 的失败不能说明浅层特征不含细节；该判断以实验 2.3 与 2.4 对同一深度特征的读出结果为准，二者结合才能区分“特征不含细节”与“模型无法直接使用该特征”。

## 4. 任务与 oracle 区域

### 4.1 任务

| 任务 | 来源 | 选用原因 |
| --- | --- | --- |
| T3 图中指定实例判断 | 实验 1.3 | 区域由问题指定的实例决定，不泄露答案，直接测量细节感知的改善 |
| T5 完整找不同 | 实验 1.3 | 测量重读能否支持实例比较与位置输出 |
| T6 显著目标定位 | 实验 1.3 | 不依赖细节感知，检验重读后坐标是否仍以原图为参照 |
| BabyVision Find the different | BabyVision 16 题 | 检验合成刺激上的结论能否适用于原始题目 |
| RefCOCO 小目标 bbox | RefCOCO val，面积占比低于 5% | 检验自然图像中的小目标定位 |

合成刺激取自实验 1.3 的主条件，限于缺口与颜色两种变化，网格规模为 10×10 与 20×20，每个单元 48 张图像。变化幅度取实验 1.3 中 T1 准确率不低于 75%、而 T3 或 T5 失败的两个等级，此时单实例的细节可以被感知，失败来自大图条件，局部重读最有可能产生作用；若实验 1.3 尚未完成，则暂取第 2 与第 3 等级。T6 每个网格规模 48 张。RefCOCO 使用实验 4.2 中面积占比低于 1% 与 1%–5% 两层样本。

### 4.2 oracle 区域

| 任务 | 区域定义 | 区域大小水平 |
| --- | --- | --- |
| T3 | 以被指定实例为中心的 $k \times k$ 个实例单元，靠近边界时整体向内平移以保持大小 | $k = 1, 3$ |
| T5、T6 | 包含目标的 $k \times k$ 个实例单元，目标在区域内的相对位置均匀随机 | $k = 3, 5$ |
| BabyVision | 依据实验 1.3 第 7 节的实例标注，取包含目标的约 3×3 个实例，目标相对位置随机 | 单一水平 |
| RefCOCO | 以目标 bbox 中心为中心、边长为 bbox 长边 3 倍的正方形，中心附加不超过半个 bbox 长边的均匀随机平移 | 单一水平 |

T3 中，$k = 1$ 只包含被指定实例，$k = 3$ 额外包含 8 个邻近实例作为比较参照，二者之差反映实例比较是否需要参照实例同时出现在重读区域中。T5 与 T6 中，目标在区域内随机放置，使区域本身不直接给出答案；区域内的随机水平为 $1/k^2$。

## 5. 指标与统计

1. **准确率差。** 对每个条件 $c$ 计算主指标 $A_c$，二值任务为准确率与 AUROC，定位任务为实例命中率或 IoU≥0.5 的比例。相对原图基线的改善为 $\Delta_c = A_c - A_{(a)}$，其 95% 区间由以图像为单位的配对 bootstrap 给出，各条件的比例另报告 Wilson 区间。
2. **配对检验。** 同一图像在两个条件下的二值结果用 McNemar 检验。预先指定的主要对比为 (c2) 对 (a)、(d) 对 (c1)、(d) 对 (e)、(d) 对 (f-d)、(c2) 对 (f-c)，多重比较使用 Holm 校正；其余对比作为探索性结果报告。
3. **区域内随机水平与平凡预测。** T5 与 T6 同时报告预测落在 oracle 区域内的比例，并以 $1/k^2$ 作为区域内随机水平。RefCOCO 另报告平凡预测的 IoU≥0.5 比例：平凡预测为以 oracle 区域中心为中心、边长为区域边长 1/3 的方框。只有超过平凡预测的部分才能归因于重读的视觉信息。
4. **坐标系错误率。** 定位任务中，将目标中心换算到 oracle 区域的局部 0–1000 坐标，若预测中心落在以该局部坐标定义的单元内而不落在原图坐标的目标单元内，则记为一次坐标系错误。该比例衡量模型是否把第二段输入的局部坐标误当作原图坐标输出。

## 6. 可视化

1. **条件对比图。** 每个任务一幅点图，横轴为条件，纵轴为 $\Delta_c$ 及其区间，有无区域提示以两种标记区分，网格规模与区域大小分面展示。
2. **逐图转移矩阵。** 对每个主要对比绘制 2×2 计数表，显示从“基线错误”到“条件正确”与相反方向的样本数，对应 McNemar 检验所用的不一致对。
3. **定位位移图。** 对 T5、T6 与 RefCOCO，在原图上绘制 (a)、(c2)、(d)、(e) 的预测点与真值，并以虚线框标出 oracle 区域，直观显示坐标系错误与区域内的选择错误。
4. **attention 去向。** 对 (d) 与 (e) 统计答案首个 token 在 gated full attention 层上分配给原图目标 token、原图其余 token 与第二段 token 的 attention 比例，作为 position IDs 作用的描述性证据。

## 7. 结果模式与解释

| 结果模式 | 解释 | 对方向二的含义 |
| --- | --- | --- |
| (c2) 显著优于 (a)，且优于 (f-c) | 细节感知受限于输入分辨率或 token 分配，重读目标区域有用 | 局部重读值得作为方向二的基本操作 |
| (b) 与 (c2) 的改善相当 | 整图分辨率不足是主要原因，聚焦局部的作用有限 | 提高输入分辨率可能是更简单的替代 |
| (d) 与 (c1) 相当，且显著优于 (a) | 缓存特征保留了足够的局部细节 | 方向二可直接复用缓存特征 |
| (d) 明显差于 (c1) | 整图上下文中编码的特征已丢失局部细节 | 方向二需要局部重编码或读取浅层特征 |
| (c2) 明显优于 (c1) | 分辨率提高带来额外收益 | 窗口读取应支持放大后重编码 |
| (d) 优于 (e)，且 (e) 的坐标系错误率更高 | 保留原图 position IDs 有助于实例对应与原图坐标输出 | 重读 token 应沿用原图行列位置 |
| (f-c)、(f-d) 相对 (a) 无改善 | 收益来自目标区域的信息，排除额外 token 的一般效应 | 窗口位置的选择是关键 |
| 有区域提示时显著优于无提示 | 模型依赖文本建立第二段输入与原图的对应 | 未经训练时需要显式提供窗口坐标 |
| 某一 (g-$\ell$) 优于 (d)，或 (g-VL-inj) 优于 (g-VL-off) | 较浅层特征对细粒度任务更有用 | 与问题 4 的结论结合，考虑在窗口读取中使用多深度特征 |
| (g-$\ell$) 不优于 (d)，但实验 2.3 显示该深度细节可读性更高 | 浅层特征含有细节，但原模型无法直接使用其投影 | 方向二需要为浅层特征训练投影 |

(d) 与 (e) 的比较与实验 3.5 关于坐标来源的结论互相印证：若 3.5 显示坐标输出主要依赖 decoder position IDs，则 (d) 对 (e) 的优势应当集中于定位任务。实验 3.5 的设计见[位置信息提取](../position/plan.md)及其坐标读取设计文档 [design_coordinate_readout.md](../position/design_coordinate_readout.md)。

## 8. 运行与产物

1. 模型使用 bfloat16，batch size 1，thinking off，greedy decoding，定位任务输出上限为 128 tokens。二值任务读取首 token 的 Yes 与 No logit，定义与实验 1.3 相同。
2. (d)、(e)、(f-d) 与 (g) 通过 model.model.get_image_features 取得视觉特征，修改后写入 inputs_embeds，并显式传入按第 3.2 节规则构造的 position_ids。每次运行先用该自定义路径重现条件 (a)，核对其 logits 与标准调用的差异在 bfloat16 数值误差以内，再运行其余条件。
3. 实验程序为 analysis_tools/reread/zoom_oracle.py，Bash 入口为 scripts/analysis/reread/zoom_oracle.sh，全部参数集中于入口顶部。合成刺激由 analysis_tools/common/stimuli.py 生成。
4. 产物保存于 WORK_DIR 的 analysis/reread/ 下，目录命名为“日期_实验名称”，例如 analysis/reread/2026-10-27_zoom_oracle/。每个目录保存模型版本、条件配置、oracle 区域与随机区域的坐标及随机种子、每条输入的 position IDs 摘要、全部 prompt 与原始回答、首 token logits、严格评分与诊断评分。文档用图复制到 docs/analysis/reread/figures/。

## 9. 解释范围与进度

1. oracle 区域由真值给定，结果是局部重读收益的上界，不代表模型能够自主选择区域。
2. (d)、(e)、(f-d) 与 (g) 在未训练条件下属于分布外输入：模型从未在训练中见过以缓存 token 构成的第二段视觉输入。这些条件下的失败不能说明经过训练后仍会失败，结论应偏保守；成功则说明原模型无需训练即可利用该输入。
3. 区域提示中的坐标本身含有位置信息。定位任务的改善需要与区域内随机水平及平凡预测比较后再作解释。
