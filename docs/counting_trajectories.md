# Counting 任务的分组观察与计数轨迹

Counting 的主要过程示范采用视觉与语言交替的形式：依据 bbox 建立空间顺序，将相邻目标合并为可辨认的观察窗口，每次读取后生成局部计数，最后生成求和过程与最终答案。物体分组、窗口大小和读取次数由目标分布及视觉分辨率共同决定。本文为数据构造方案，尚未实现或验证训练效果。

## 1. 输入标注与完整性

输入为原图、计数问题、目标实例的 point 或 bbox，以及原始总数答案。每个被查询的实例分配稳定 ID；同一实例的重复点先合并。点到候选实例框的转换采用 [几何估计或 SAM 分割](point_to_window.md)。实例类别、属性和可见性规则必须与计数问题一致。

过程标注要求确认目标实例集合完整，并使去重后的实例数与原始总数一致。总数相等之外，还需检查漏标与错误实例是否相互抵消。分割合并、重复 mask、同一对象的多个部件、只标出部分目标的记录分别审核。标注冲突保留原始答案和失败原因，修复完成后再构造完整过程。

总数用于离线核验、难度分层及资源估计。VLM 在初始图像和问题之后自主选择窗口与停止时机；推理控制器不读取答案、实例清单、分组标签或计划窗口总量。

## 2. 基于 bbox 的空间排序

采用从上到下、行内从左到右的示范顺序。读取源 point 数组后重新排序，顺序由审核后的 bbox 决定。

1. 计算各 bbox 的中心、宽高及四条边界，统一使用长边归一化坐标。
2. 按中心纵坐标预排序。规则排列的目标按行分组；首版允许同一行的中心纵坐标跨度不超过该行 bbox 高度中位数的 0.5 倍。逐个加入目标并重新检查跨度，避免通过相邻点链式连接将多行并为一行。阈值由独立标注开发集校准。
3. 行间按中心纵坐标中位数递增排列，行内按 bbox 左边界递增排列。平局依次用中心纵坐标、右边界和稳定实例 ID 消解。
4. 大小差异明显或不形成自然行的布局，采用固定配置的水平扫描带，将 bbox 中心归入扫描带；扫描带从上到下，各带内从左到右。扫描带高度由目标尺度与开发集配置确定，归属规则仅用于排序。

行或扫描带确定后，分组始终使用该顺序中的连续目标。每个观察组按其首个目标的排序位置执行。上下文扩展造成窗口中心变化时，仍保留原分组顺序。离线记录排序配置与最终实例序列，支持轨迹重放检查。

该顺序提供一致的扫描示范。模型自主执行时可采用其他正确策略，任务评分仍依据计数结果与过程是否重复、遗漏。

## 3. 动态分组与窗口合并

### 3.1 候选分组

从排序后尚未分组的第一个实例开始，逐个尝试加入相邻实例。组的基础窗口取成员 bbox 的最小轴对齐包围框，再增加适度上下文。初始配置可将每组目标数量上限设为 6，作为试制参数；实际组大小允许从 1 到该上限变化。

每次加入目标，均检查以下条件：

- **空间紧凑性：** 相邻 bbox 的间隙和合并窗口面积增量在配置允许范围内，避免将远隔的对象强行纳入同一窗口。
- **可辨性：** 组内最小目标在缓存特征及本次读取的局部取样网格中仍能提供足够细节，允许的最小覆盖量由实际 VLM 配置和开发集确定。
- **边界与计数独立性：** 目标获得足够完整的可见证据，窗口内其他被查询目标的归属已经核查，具体规则见第 4 节。

加入下一个目标后不满足条件时，先结束当前组，再从下一个实例开始。相邻行的组可进一步提出合并候选，但仍需满足连续顺序及上述条件。目标很少且全局可辨时，可以只读取一次整图或目标联合区域。

每步参考区域需满足模型的位移与尺度约束。可从整图区域 0 定位，或在目标窗口可达时引用前序窗口；观察顺序与参考区域选择分别记录。

单个实例也无法在缓存中辨认时，应检查视觉编码的分辨率。扩大窗口或增加步骤的效果需以实际特征为准。该样本保留为感知失败或待处理记录。

### 3.2 总数与窗口预算

窗口总量是分组结果。原始总数可以帮助估计最低可能组数和制数成本，具体划分继续服从位置、尺度和可辨性约束。相同物体总数的样本可以产生不同窗口数量，相同窗口数量的样本也应覆盖不同总数。

例如 36 个清晰目标若每组均可容纳 6 个，可形成 6 次读取；目标更小、更分散或存在遮挡时需要更多读取。该例仅说明分组的潜在收益。每组上限的配置在不同数量范围保持共同规则，并可在开发集允许范围内采样，以增加组大小变化。

读取上限由模型配置统一给出，达到预算时执行既定终止规则并保留失败。离线构造阶段对超过预算的示范继续检查分组或归入困难数据，完整目标清单和答案保持一致。

初始 VLM 已获得整图；示范中可增加对空区域、稀疏区域或疑似遗漏区域的检查，局部结果允许为 0。全局覆盖与停止依据纳入审核，避免仅保留直接跳转所有已知目标的示范。

## 4. 覆盖与去重

### 4.1 独立分组计数

首版优先采用 `exclusive` 模式：每个目标恰好在一个计数窗口中出现并被计入，窗口之间可重叠背景。合并与扩展后重新检查所有被查询实例，防止包围框额外包含其他目标。

窗口触及其他目标时，可缩减上下文、调整分组，或将相邻组按空间顺序合并并重新检查可辨性。矩形范围内夹入其他实例的情况也按此规则处理。检查时优先使用可靠 mask；仅有 bbox 时采用保守的相交检查。先前组涉及的目标受到影响时，需要共同重新构造。

每个目标仅属于一个离线组这一条件，还需由实际可见内容支持。通过审核的独立窗口，其局部计数就是该窗口的目标数。各组实例集合互不相交，并集等于完整目标集合。

### 4.2 重访与新增计数

对于需要交叠观察或重查的困难样本，采用 `new_instances` 模式。每步区分窗口中的可辨认目标和其中尚未计入的目标。例如：“这个窗口有 5 个，其中左侧 2 个在上一窗口已经计入，本次新增 3 个，累计 9 个。”重复目标的对应关系应能从实际图像、读取历史及文本中判断。

训练时使用实例 ID 核验去重；模型上下文通过视觉观测及生成语言保留对应关系。仅在离线 ID 层面能区分、视觉上仍存在歧义的轨迹进入审核。重访已数区域可以新增 0 个；最终求和使用各步新增数量。

两种计数模式在离线元数据中明确记录。主训练样本优先采用独立分组，困难样本逐步加入重访计数，并单独评价重复与遗漏错误。

## 5. 语言过程与最终答案

Counting 的主要示范使用 `interleaved`。每次 `visual_read` 后紧跟 `reasoning_text`，记录局部数量及累计数量。完成全部观察后，另一个语言事件列出各步新增数量并求和，再执行 `finish` 和最终答案生成。

示例事件顺序如下：

```text
观察上方区域 → “上方区域有 6 个，累计 6 个。”
观察中间区域 → “中间区域有 5 个，累计 11 个。”
观察下方区域 → “下方区域有 4 个，累计 15 个。”
汇总 → “三组分别是 6、5、4 个，6 + 5 + 4 = 15。”
结束中间推理 → 最终答案 15
```

这些文本是 SFT 的生成目标；自主推理与 GRPO 中由模型根据实际观测生成。执行器只返回视觉特征和几何信息，局部计数和求和由模型完成。局部语言必须与该步已取得的信息一致，总数标签仅在监督和评分侧使用。

保留 `visual_only` 对照，用相同几何操作和最终答案训练内部累计；纯视觉模式没有中间计数文本，独立验证累计能力。两种模式的版本属于同一数据划分。零目标样本可观察整图、生成数量为 0 的说明并回答；可直接判断的少量目标也保留直接回答样本。

## 6. 数据字段与完整性检查

标准事件格式保持不变，几何信息使用长边归一化坐标。`answer` 采用 `number`，值为非负整数。离线扩展字段 `metadata.counting` 是 object，包含以下必填字段：

| 字段 | 类型与定义 |
| --- | --- |
| `config_id` | 非空 string，关联排序、分组、可辨性及边界检查配置 |
| `mode` | `exclusive` 或 `new_instances` |
| `instance_order` | string 数组，按 bbox 空间排序的完整目标 ID 序列；零目标时为空 |
| `audit_record_path` | 相对 `DATA_DIR` 的非空路径，关联实例标注、mask 或 bbox、窗口覆盖审核与失败说明 |
| `groups` | object 数组，按实际读取顺序保存下表记录；仅直接回答时为空 |
| `sum_event_id` | 汇总语言事件的正整数编号；纯视觉和直接回答时为 null |

每个 `groups` 元素含以下字段：

| 字段 | 类型与定义 |
| --- | --- |
| `read_event_id` | 正整数，对应一次 `visual_read` |
| `count_event_id` | 对应该步计数文本的正整数事件编号；纯视觉时为 null |
| `visible_instance_ids` | 当前窗口中具有充分可辨认证据的目标 ID 数组，允许为空 |
| `new_instance_ids` | 该步首次计入的目标 ID 数组，允许为空 |
| `local_count` | 非负整数，等于 `visible_instance_ids` 长度 |
| `new_count` | 非负整数，等于 `new_instance_ids` 长度 |
| `cumulative_count` | 非负整数，等于截至本步各 `new_count` 之和 |

所有 ID 数组内部唯一。新增集合等于当前可辨认集合减去先前已计入集合；独立模式下可辨认集合与新增集合相同。审核文件还需列出被窗口截断或难以辨认的目标，检查它们是否导致计数歧义或遗漏。合格轨迹的新增集合两两不交，并集等于 `instance_order`，累计结果与最终答案一致。

检查语言事件中的局部数量、累计数量、求和项与这些记录一致，检查读取引用合法及空间顺序正确。`metadata.counting` 全部保留在监督与审核侧。模型输入不包含实例 ID、局部计数元数据或计划窗口数。直接回答记录不要求构造虚拟观察组，其最终答案单独核验。

由多个 point 合成的窗口，在 `metadata.window_derivations` 中关联该视觉事件涉及的来源点及审核配置。标准 `region` 始终表示实际窗口，实例框保存在离线审核文件中。

[JSONL 格式示例](examples/visual_reasoning_samples.jsonl) 中的 `counting_grouped_demo` 提供三次读取、逐步计数与汇总事件；配套 [离线标注](examples/counting_annotations.json) 故意倒序保存实例，用于核查按 bbox 重新排序及分组覆盖。二者均为格式示例，图像和实际特征可辨性尚未验证。

## 7. 效率与泛化评价

比较逐实例读取、分组读取和直接作答；同时比较纯视觉与视觉语言交替模式。统计最终准确率、局部计数错误、重复计数、漏计、算术错误、读取次数、视觉 token、语言 token、总延迟和显存。

按总数、密度、尺度、遮挡和组大小分层评价。窗口合并会减少读取次数，也可能降低每个目标分配到的局部取样密度；中间语言会增加 token。端到端收益以实测结果为准。离线 SAM 制数成本和模型推理成本分别记录。

用相同总数不同布局、相同窗口数不同总数、包含空区域与重访的样本检查策略泛化，保留所有失败。过程验证集与外部测试独立，计数 ground truth 不控制测试时的读取预算或停止。
